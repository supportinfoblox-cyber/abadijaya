TICKETOPS ENTERPRISE

Spesifikasi Arsitektur Sistem, Topologi, dan Tumpukan Teknologi (Tech Stack)
VERSI PRODUKSI 1.0

Target: BSI Infoblox & iCare OTRS
Pengembang: PT Abadi Jaya Solusi
Dokumen Dibuat: September 2026
Ringkasan Eksekutif: TicketOps adalah sistem manajemen operasional tiket enterprise multi-platform (Web SPA & Android Native) dengan arsitektur Hybrid Cloud-First & Local-First Resilient. Sistem mengintegrasikan database relasional real-time cloud, background sync daemon untuk sistem perbankan legacy iCare OTRS, enkripsi data end-to-end, dan pemrosesan otomatis klasifikasi tiket berbasis AI heuristic.

1. Topologi Arsitektur Sistem (System Topology)

Topologi TicketOps dirancang menggunakan pola 4-Tier Hybrid Cloud & Edge yang mengombinasikan ketahanan offline (local-first) dengan sinkronisasi multi-pengguna real-time di cloud:

A. Komponen Edge & Distribusi Global

  • Cloudflare Pages (Global Edge Network): Menyajikan bundle aset statis terkompresi Brotli/Gzip dengan latensi rendah di seluruh region edge server.
  • Domain & TLS: Otomatisasi enkripsi HTTPS/TLS 1.3 pada ticketops.pages.dev.
  • Pertahanan Header: Content-Security-Policy (CSP), X-Frame-Options: DENY, X-Content-Type-Options: nosniff, dan Referrer-Policy.

B. Komponen Database & Sinkronisasi Hybrid

  • Cloud Source of Truth: PostgreSQL di Supabase Cloud mengelola status data secara terpusat untuk kolaborasi antarteknisi.
  • Local-First Resilience: Jika jaringan internet terputus, aplikasi tetap berfungsi normal membaca cache lokal terenkripsi, lalu menyinkronkan perubahan saat online.
  • Realtime Event Stream: Notifikasi dan pembaruan tiket didistribusikan via protokol WebSocket Postgres CDC.

4. Detail Arsitektur Frontend

Frontend TicketOps dibangun dengan prinsip Zero-AI-Slop & High-Density Operational UI, dirancang untuk kecepatan navigasi dan kepadatan data teknis tanpa mengorbankan estetika modern:

A. UI/UX Design System

  • Styling: Pure Vanilla CSS berbasis Design Tokens (CSS Variables) pada src/app/globals.css.
  • Tema Ganda: Dark mode (default operator NOC) dan Light mode yang harmonis dengan kontras teks bersertifikasi WCAG AA.
  • Glassmorphism & Micro-Interactions: Efek glass panel transparan, border subtle rgba(255,255,255,0.08), dan transisi halus.
  • Ikonografi: Lucide React (v1.42.0) — icon set vektor ringan, konsisten, dan scalable.

B. State Management & Routing

  • TicketOpsContext: Single source of truth mengelola 14 modul operasional, autentikasi pengguna, antrean tiket, sinkronisasi Supabase, dan pencarian global.
  • Client-Side Router: Custom History API router (src/lib/router.ts) yang mendukung deep-linking, back/forward history browser, dan dynamic page title tanpa reload.
  • Inactivity Timeout Engine: Deteksi interaksi pengguna (mouse, touch, keydown) dengan auto-logout setelah 30 menit nonaktif.

5. Detail Arsitektur Backend, Database & Integrasi

A. Database: Supabase Cloud (PostgreSQL 15+)

  • Relational Tables:
    • tickets: Metadata tiket, nomor OTRS, prioritas, kriteria, requester, due date, status.
    • worklogs: Durasi pengerjaan teknisi, deskripsi tugas, foreign key ke tiket.
    • audit_logs: Append-only ledger mencatat setiap aksi pengguna dan timestamp.
    • users: Akun teknisi, role permissions, PBKDF2 password hash, status aktif.
    • ms_devices: Data appliance Infoblox dan status lisensi.
  • Security & RLS: Row Level Security memastikan pembatasan akses data antarentitas.
  • Realtime Channels: Broadcast perubahan data secara instan tanpa perlu polling HTTP dari browser.

B. Daemon Sinkronisasi & OTRS Bridge

  • Node.js Daemon (sync_otrs_to_supabase.mjs): Worker mandiri yang melakukan query berkala setiap 180 detik ke API iCare OTRS, menormalisasi data tiket ke format standar, dan melakukan upsert ke tabel Supabase.
  • Python 3 Bridge Subsystem:
    • otrs_login_bridge.py: Menangani otentikasi session cookie iCare OTRS.
    • otrs_close_bridge.py: Menutup tiket secara otomatis di sistem iCare OTRS saat tiket di-resolve di TicketOps.
    • otrs_history_fetcher.py: Mengambil riwayat arsip tiket historis dari antrean iCare OTRS.
  • Vite API Gateway Middleware: Menyediakan endpoint proxy lokal terproteksi (/api/otrs/*) dengan rate limiting dan validasi origin.

7. Matriks Keamanan & Kepatuhan Regulasi

Fitur Keamanan Spesifikasi Teknis Standar Regulasi / Manfaat
Password Hashing PBKDF2-SHA256, 100.000 iterasi, 16-byte random salt, verifikasi constant-time string. NIST SP 800-63B & UU PDP Psl 35 — Kebal terhadap serangan brute-force dan timing attacks.
Storage Encryption RFC 7516 JWE 256-bit AES-GCM untuk sessionStorage dan localStorage. Anti-DevTools Leak — Menghindari pembacaan data mentah token/sesi melalui konsol browser.
Inactivity Timeout Auto-logout 30 menit tanpa aktivitas pengguna dengan multi-tab storage sync. SOC 2 Trust Criteria CC6.1 & ISO 27001 A.8.1 — Mencegah pembajakan sesi di perangkat tak terjaga.
HTTP Security Headers CSP (frame-ancestors 'none'), X-Frame-Options: DENY, X-Content-Type-Options: nosniff. OWASP Top 10 — Menutup 100% celah Clickjacking, XSS, dan MIME-sniffing di Cloudflare.
Anti-Prototype Pollution Sanitasi key objek ketat memblokir __proto__, constructor, prototype. Menjamin stabilitas runtime JavaScript dari injeksi manipulasi prototipe objek.
Audit Trail Logging Pencatatan kronologis IP address, user, modul, oldValue, dan newValue per mutasi. ISO/IEC 27001:2022 Kontrol A.8.15 & SOC 2 CC7.2 — Jaminan akuntabilitas dan non-repudiation.
